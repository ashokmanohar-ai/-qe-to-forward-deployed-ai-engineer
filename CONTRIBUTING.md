# Contributing

Contributions should make the transition path more practical, verifiable, inclusive, or current.

## Good contributions

- a reproducible lab with a clear failure mode and solution;
- a customer scenario with discovery questions and measurable outcomes;
- an evaluation dataset that contains no confidential or personal data;
- a correction supported by primary documentation;
- an accessibility, security, or reliability improvement.

## Workflow

1. Open an issue describing the learner problem.
2. Create a focused branch and add tests or validation where relevant.
3. Run `make check`, `make test`, and `make docs`.
4. Open a pull request using the template.

Do not commit credentials, customer data, proprietary prompts, copyrighted course material, or generated content that has not been reviewed for accuracy.

## Content standard

Every tutorial should state prerequisites, learning outcomes, steps, verification, failure injection, cleanup, and evidence. Every project should state scope, non-goals, acceptance criteria, operational considerations, and an interview narrative.
